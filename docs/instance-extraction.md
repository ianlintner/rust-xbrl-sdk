# XBRL 2.1 instance syntax extraction — milestone 3

Authority: XBRL 2.1 Recommendation 31 December 2003, corrected errata 20 February 2013, §§4.1–4.8, [normative text](https://www.xbrl.org/Specification/XBRL-2.1/REC-2003-12-31/XBRL-2.1-REC-2003-12-31+corrected-errata-2013-02-20.html), Appendix A; XML 1.0 5th edition; Namespaces in XML 1.0 3rd edition; XML Schema Part 2. This is **syntax extraction**, not XBRL validation or filing certification.

`xbrl_xml::instance::parse_instance(source, limits)` uses the bounded XML reader and returns `xbrl_core::instance::Instance` or a rule-coded diagnostic with source span. No schema/taxonomy is fetched. Successful extraction only means the supported syntactic subset was extracted; it does **not** mean the source is a valid XBRL document. The CLI parse command remains unimplemented.

Supported: direct item elements with expanded concept QName (equality/hash ignore lexical prefix), raw lexical value or xsi:nil, optional ID, contextRef and unitRef; contexts with entity identifier/scheme, period date/dateTime or forever, and preserved segment/scenario extension subtrees; simple/product/divide units with expanded QName measures; decimals/precision (integer or `INF`); schemaRef href and root/element xml:base chain. Reference values and href targets are **not resolved**. Extension trees retain element names, attributes, direct text and child order, but interleaving of direct text and child elements is not round-trippable.

Fail closed: malformed XML, DOCTYPE, resource limits, missing required syntactic fields, invalid structure/date/accuracy/measure QName, unsupported tuple/complex/fraction items, linkbase/role/arcrole refs and footnotes. An unprefixed measure with no bound default namespace cannot be represented by the current `QName` type and is rejected; XML Schema QName semantics and such measure types need a future model extension. Numeric accuracy is represented in i64/u64; larger legal XML Schema integers report `unsupported` instead of being truncated.

The extractor enforces document-wide uniqueness of context, unit and fact XML IDs; this is *not* reference resolution or a full validity check. XML Schema whitespace collapse applies only to XML whitespace (#x20, #x9, #xA, #xD), not Unicode whitespace. An empty entity identifier is accepted because the Appendix A type does not impose a `minLength`. A date-only endDate/instant denotes the next midnight; startDate is the start of its date. Equal date-only start/end values therefore describe a one-day duration. Zone-less versus zoned durations are rejected only when reversed under every permitted ±14-hour interpretation. Dates support positive years of four to nine digits (including expanded years), and reject negative years and years longer than nine digits as *unsupported*, not as valid. Period strings retain accepted lexical spellings/time zones; they are validated on extraction but are not guaranteed canonical. `xsi:nil` values use XML Schema boolean lexical forms (including whitespace collapse). Fact text coalesces text, CDATA, character references and spans across comments/PIs (`1<!--x-->2` yields `12`).

Not implemented here: DTS membership and concept data types, context/unit reference target existence, periodType compatibility, numeric value typing, fraction typing, nil type restrictions, unit simplification and currency restrictions, xml:base resolution, schema target validation, dimensions, footnote XLinks and tuple semantics. Those belong to taxonomy/validation phases. Incomplete support must never be used as a green validity verdict.

Memory: direct facts and schemaRefs are finalized at their end tags without a full-document DOM. Only the current context or unit subtree is buffered; in-scope namespace bindings are shared on a single stack and resolved at a measure's end tag. Reader byte/depth/token/attribute/namespace limits plus `Limits::max_instance_elements` (default 1,000,000; `xbrl-instance:limit-elements` on N+1) bound extraction. The model output still grows with input size; this is not a constant-memory parser. No benchmark-performance guarantee is asserted.

These six extraction assertions are **not** full official conformance variations: official pass/fail/unsupported counts for the complete suite remain **0 run / not assessed**. In particular, the official 303-03/303-04 invalidities require taxonomy periodType checking and must not be counted as parser failures.
